# OpenAI Decisions Claude RAG aggregates

## TL;DR

All four decision-model filters reduced the context sent to Claude, and the common GLM 5p3 Flash judge favored the filtered answers on this 100-question sample. In threshold mode, GLM accepted 80 unfiltered answers, 87 Jev 1.13-filtered, 87 Jev 1.14-filtered, 89 Decisions-filtered, and 92 SubQ-filtered; Decisions and SubQ improved on baseline by +9 points [+2, +16] and +12 [+5, +19], while both Jev versions' +7 intervals touched zero. In categorical mode, the scores were 80, 81, 91, 89, and 90, with Jev 1.14 +11 [+4, +18], Decisions +9 [+3, +15] and SubQ +10 [+3, +18]. These answer differences do not isolate the filter: baseline and Jev 1.13 answers used Claude Code Max, whereas Jev 1.14, Decisions and SubQ used Team, and Jev 1.13's own filter decisions scored 3 and 6 points higher when answered on Team. With both Jev versions answered on Team and scored in one GLM pass, Jev 1.14 − Jev 1.13 was −3 points [−8, +1] in threshold mode and +6 [+1, +12] in categorical mode, against a noise floor of about ±3 points from Claude's answer variation and judge repeatability. SubQ retained 264 threshold chunks and 292 categorical chunks and Jev 1.14 retained 308 and 378, compared with Jev 1.13's 322 and 420. GLM is also a model judge, not human ground truth, and used its supported low-reasoning mode. The results support substantial context reduction, but provider rankings remain confounded by route and sample.

The common-judge aggregates report scores, paired intervals, judge agreement, and usage for [threshold mode](../glm-5p3-threshold-common-judge-v1/rejudge-comparison.jsonl) and [categorical mode](../glm-5p3-categorical-common-judge-v1/rejudge-comparison.jsonl).

[`summary.json`](summary.json) holds the source-free numbers behind the [provider comparison](../../README.md#provider-comparison). It was generated by `publication/decisions-aggregates.py` in the private repository and lists every private source file it read with its SHA-256 (`sources`). It contains numbers and machine identifiers only; no EnronQA questions, reference answers, chunks, generated answers, receipts or raw provider responses.

Under `data.modes.threshold` and `data.modes.categorical`:

- `same_judge_correct`: answers accepted by `deepseek-v4p1-flash` for the unfiltered, Jev 1.13 and Decisions arms under the same judge model and prompt.
- `same_judge_discordant` and `same_judge_paired_intervals`: questions answered correctly by only one of two arms, and paired differences with 95% cluster-bootstrap intervals by source document (descriptive).
- `chunks`, `per_result_on_identical_inputs`, `returned_context_proxy_tokens`: chunks kept and returned, chunk-level agreement with the Jev 1.13 filter (and, for categorical mode, the category confusion matrix), and context size.
- `filter_stage`, `refused_results`, `answer_stage_latency_s`, `estimated_api_equivalent_usd`, `source_coverage`: Decisions requests, tokens and cost, refusals (none), answer-stage timings for the Decisions and Jev 1.13 arms, API-equivalent pipeline cost estimates, and initial-search source coverage.

`data.rescore_judge` reports Decisions as an answer judge on the frozen answers: acceptances, agreement with the frozen DeepSeek and Jev 1.13 rescoring verdicts, requests, tokens, cost and latency.

The Decisions arms' Claude answers came through Claude Code on a Team subscription; the frozen arms used Claude Code Max. Claude costs are API-equivalent list estimates, not subscription charges.
