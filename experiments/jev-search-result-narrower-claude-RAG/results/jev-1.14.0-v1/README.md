# Jev 1.14 Claude RAG aggregates

## TL;DR

All four decision-model filters reduced the context sent to Claude, and the common GLM 5p3 Flash judge favored the filtered answers on this 100-question sample. In threshold mode, GLM accepted 80 unfiltered answers, 87 Jev 1.13-filtered, 87 Jev 1.14-filtered, 89 Decisions-filtered, and 92 SubQ-filtered; Decisions and SubQ improved on baseline by +9 points [+2, +16] and +12 [+5, +19], while both Jev versions' +7 intervals touched zero. In categorical mode, the scores were 80, 81, 91, 89, and 90, with Jev 1.14 +11 [+4, +18], Decisions +9 [+3, +15] and SubQ +10 [+3, +18]. These answer differences do not isolate the filter: baseline and Jev 1.13 answers used Claude Code Max, whereas Jev 1.14, Decisions and SubQ used Team, and Jev 1.13's own filter decisions scored 3 and 6 points higher when answered on Team. With both Jev versions answered on Team and scored in one GLM pass, Jev 1.14 − Jev 1.13 was −3 points [−8, +1] in threshold mode and +6 [+1, +12] in categorical mode, against a noise floor of about ±3 points from Claude's answer variation and judge repeatability. SubQ retained 264 threshold chunks and 292 categorical chunks and Jev 1.14 retained 308 and 378, compared with Jev 1.13's 322 and 420. GLM is also a model judge, not human ground truth, and used its supported low-reasoning mode. The results support substantial context reduction, but provider rankings remain confounded by route and sample.

The common-judge aggregates report scores, paired intervals, judge agreement, and usage for [threshold mode](../glm-5p3-threshold-common-judge-v1/rejudge-comparison.jsonl) and [categorical mode](../glm-5p3-categorical-common-judge-v1/rejudge-comparison.jsonl).

[`summary.json`](summary.json) holds the source-free numbers behind the Jev 1.14 column of the [provider comparison](../../README.md#provider-comparison) and the [same-route comparison](../../README.md#jev-113-and-jev-114-on-the-same-route). It was generated by `experiments/rag-filtering-claude/scripts/jev-1.14.0-public-aggregates.py` in the private repository and lists every private file it read with its SHA-256 (`sources`). It contains numbers and machine identifiers only. It has no EnronQA questions, reference answers, email text, retrieved chunks, generated answers, question identifiers, receipts or raw provider responses.

## Fields

Under `modes.threshold` and `modes.categorical`:

- `same_route_common_judge`: the like-for-like comparison. Jev 1.13 and Jev 1.14 filter decisions were both answered by Claude Opus 5 through Claude Code Team and scored in one pass by `accounts/fireworks/models/glm-5p3-flash` (reasoning effort `low`, frozen judge prompt hash in `judge_prompt_sha256`). It holds accepted answers, the paired Jev 1.14 − Jev 1.13 difference with discordant counts, and three noise-floor measures:
  - `identical_keep_set_split`: the same comparison on questions where both versions kept exactly the same chunks, and on the rest.
  - `answer_text_repeatability`: how many of Claude's answers were byte-identical across the two versions, overall and on identical evidence.
  - `jev_1_14_verdict_repeatability_across_two_passes`: how often two GLM passes over the same Jev 1.14 answers gave the same verdict.
- `route_effect_jev_1_13_team_minus_max`: GLM verdicts on Jev 1.13's filter decisions answered on Team versus on Max.
- `provider_table_common_judge`: the Jev 1.14 column of the provider table, with paired differences against the unfiltered and Jev 1.13 answers. Those two arms were answered on Claude Code Max, so these differences mix filter and route effects.
- `secondary_judge_deepseek_v4p1_flash`: the same-route comparison under the DeepSeek v4p1 Flash judge.
- `jev_1_14_vs_jev_1_13_on_identical_inputs`: chunk-level keep/drop agreement on the 2,000 identical initial-search chunks: counts, agreement, Cohen's κ, the probability correlation for threshold mode, and the category confusion matrix for categorical mode.
- `filtering` and `filter_resources`: chunks scored and kept (including follow-up searches), pages, categories, initial-search source coverage and maximum page size. Also filter requests, HTTP status counts, the `model` field of every response, input tokens, list-price cost (Jev input at $0.042 per million, output free), and page and per-search timings for both versions.
- `claude_answers`: Claude input (including cache writes and reads) and output tokens, list-price Claude cost, whole-pipeline API-equivalent cost, chunks returned and time to answer. Each arm is labeled with its route.

Intervals are 95% cluster-bootstrap intervals by source document (5,000 resamples, seed 20260918), descriptive and unadjusted.

## Scope

All arms share the same 100 questions, initial retrieval, paging guards, Claude Opus 5 model and prompts, and judge protocol. Jev 1.14 was called by its pinned id `jev-1.14.0`. All 839 Jev 1.14 filter pages succeeded on the first attempt, every Claude answer call succeeded, and the offline audit passed in both modes. The GLM judge returned transient HTTP 5xx and transport errors; resumable retries collected every judgment, and no item is missing or excluded. The unfiltered reference was answered only on Claude Code Max. Claude costs are API-equivalent list estimates, not subscription charges, and timings for the two Jev versions were measured under different service conditions.
