# Jev 1.14 Kimi RAG aggregates

## TL;DR

Jev 1.14 (`jev-1.14.0`) and Jev 1.13 (`jev-1.13.0`) were indistinguishable as filters. The common GLM 5p3 Flash judge accepted 94/100 Jev 1.14-filtered answers, 93 Jev 1.13-filtered and 94 unfiltered. Jev 1.14 − Jev 1.13 was +1 point [−2, +5], and Jev 1.14 − unfiltered was 0 [−5, +5]. When the judge scored all three arms in a single pass, the result was 94 / 95 / 91, so Jev 1.14 − Jev 1.13 became −1 [−5, +2]. That judge variation of up to 3 points per arm is larger than the gap between the two Jev versions. On the same 2,000 chunk decisions, Jev 1.14 kept 283 chunks and Jev 1.13 kept 306, and they agreed on 98.25% of keep/drop decisions (Cohen's κ 0.930). Kimi K3 therefore read 231,515 input tokens instead of 247,705. The estimated whole-pipeline cost was $1.63 per 100 questions, compared with $1.65 for Jev 1.13 and $5.06 unfiltered. GLM is a model judge rather than human ground truth, and these are list-price estimates rather than invoices.

[`summary.json`](summary.json) holds the source-free numbers behind the Jev 1.14 row of the [provider comparison](../../README.md#provider-comparison). It was generated by `experiments/rag-filtering-kimi/scripts/jev-1.14.0-public-aggregates.py` in the private repository and lists every private source file it read with its SHA-256 (`sources`). It contains numbers and machine identifiers only. It has no EnronQA questions, reference answers, email text, retrieved chunks, generated answers, question identifiers, receipts or raw provider responses.

## Fields

- `common_judge.primary_scores` and `primary_paired`: answers accepted by `accounts/fireworks/models/glm-5p3-flash` (reasoning effort `low`) for the unfiltered, Jev 1.13 and Jev 1.14 arms, plus paired differences in points with 95% cluster-bootstrap intervals by source document (5,000 resamples, seed 20260918, descriptive and unadjusted). These are the same GLM verdicts on the unfiltered and Jev 1.13 answers that appear in the [common-judge aggregate](../glm-5p3-common-judge-v1/rejudge-comparison.jsonl).
- `common_judge.single_pass_all_arms_scores` and `single_pass_all_arms_paired`: a second GLM pass over all three arms under the same protocol. `repeatability_single_pass_vs_primary` compares the two passes on identical answers. `attempts_by_http_status`, `ok_latency_s` and the token counts describe that judge's service behaviour.
- `secondary_in_run_judges_two_arms`: the Jev 1.14 and DeepSeek v4p1 Flash answer judges, which scored only the unfiltered and Jev 1.14 arms. They are not a like-for-like comparison with Jev 1.13.
- `filtering` and `jev_1_14_vs_jev_1_13_on_identical_inputs`: chunks scored and kept by each version, initial-search source coverage, maximum page size, and chunk-level agreement on the 100 identical initial result sets (counts, keep agreement, Cohen's κ, mean probability difference, and the number of result sets whose keep set changed).
- `filter_resources`: filter requests, failures, retries, the `model` field in every response, tokens, list-price cost (Jev input at $0.042 per million, output free) and page round-trip times for both versions.
- `kimi`: Kimi K3 requests, input (cached) and output tokens, list-price cost, chunks and proxy tokens returned to Kimi, search calls, and answer elapsed time for each arm. That elapsed time includes the initial filter stage.
- `answering_pipeline_cost_estimates`: whole answering-pipeline list-price estimates for Kimi, filtering, reranking and query embeddings under the three caching assumptions used throughout this experiment. The Jev 1.14 arm made no follow-up searches, so its search cost is the 100 initial searches.

## Scope

All arms share the same 100 questions, initial retrieval, filter pages, Kimi K3 prompt and judge protocol. The Jev 1.14 arm's Kimi answers are separate generations, so Kimi's own run-to-run variation is part of every arm difference, as it is for the other filter providers. All 403 Jev 1.14 filter requests and all 100 Kimi answers succeeded on the first attempt. The GLM judge returned 100 transient HTTP 502/504/530 or transport errors across 400 attempts; resumable retries collected every judgment, and no item is missing or excluded. Filter and Kimi timings for the two Jev versions were measured under different service conditions, so they are descriptive rather than a controlled latency comparison.
