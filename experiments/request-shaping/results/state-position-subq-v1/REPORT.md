# Study 3 results: position in state (subq)

Generated by `state-position report` from saved receipts. SubQ Snap `subq-snap-preview`; every judged BM25 candidate of 20 seeded TREC DL queries is a target. Each target is placed among 9 or 39 fixed off-topic filler passages (drawn from other queries' candidates), at the start, 25%, middle, 75%, or end of the `passages` array; only the target's position changes. **Pointed** asks about the target by its opaque id. **Needle** asks whether any passage is useful, so a relevant target must be found without a pointer. Unless named `qfirst`, the question field follows the passages. AUC separates grade ≥ 2 targets from the rest. Intervals are 95% query-cluster bootstrap intervals (2,000 replicates) stratified by year.

**Provider:** SubQ Snap decisions API, model `subq-snap-preview`, endpoint `https://api.subq.ai/v1/systemone`, body preparation `v1`. Every provider receives the same planned request content. SubQ changes only `model`; `payload_sha256` identifies the shared plan and `sent_request_sha256` identifies the exact sent body. State and questions are byte-identical and nothing is translated. No `reasoning_effort`, images or options are sent.

**Execution settings:** 4 workers, up to 4 attempts per request (transport, 408, 429 and 5xx retried; Retry-After honored), HTTP timeout 120s.

**Jev comparison:** `jev-1.13.0` columns use the same plan and request bodies from `results/state-position-v1`.

**Response model echo:** `subq-snap-preview` (32454 requests).

**Noise floor:** this study has no retest arm. Read SubQ Snap differences against the SubQ Snap retest noise measured by the retest arms in Studies 1 and 2 (`state-packing` `retest`, `question-fanout` `retest-useful`), not against Jev's.
