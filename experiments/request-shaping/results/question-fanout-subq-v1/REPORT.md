# Study 2 results: question fan-out (subq)

Generated by `question-fanout report` from saved receipts. SubQ Snap `subq-snap-preview`; 20 seeded TREC DL queries (10 per year) × 100 BM25 candidates = 2,000 items. Every arm has the same one-passage state; only the questions in the request change. The scored target is always the frozen `useful` relevance question. Intervals are 95% query-cluster bootstrap intervals stratified by year; Holm covers the eight fan-out contrasts.

**Provider:** SubQ Snap decisions API, model `subq-snap-preview`, endpoint `https://api.subq.ai/v1/systemone`, body preparation `v1`. Every provider receives the same planned request content. SubQ changes only `model`; `payload_sha256` identifies the shared plan and `sent_request_sha256` identifies the exact sent body. State and questions are byte-identical and nothing is translated. No `reasoning_effort`, images or options are sent.

**Execution settings:** 4 workers, up to 4 attempts per request (transport, 408, 429 and 5xx retried; Retry-After honored), HTTP timeout 120s.
