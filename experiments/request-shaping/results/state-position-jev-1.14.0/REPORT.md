# Study 3 results: position in state (jev-1.14.0)

Generated by `state-position report` from saved receipts. Jev 1.14 (`jev-1.14.0`); every judged BM25 candidate of 20 seeded TREC DL queries is a target. Each target is placed among 9 or 39 fixed off-topic filler passages (drawn from other queries' candidates), at the start, 25%, middle, 75%, or end of the `passages` array; only the target's position changes. **Pointed** asks about the target by its opaque id. **Needle** asks whether any passage is useful, so a relevant target must be found without a pointer. Unless named `qfirst`, the question field follows the passages. AUC separates grade ≥ 2 targets from the rest. Intervals are 95% query-cluster bootstrap intervals (2,000 replicates) stratified by year.

**Provider:** TypeSafe Jev, model `jev-1.14.0`, endpoint `https://typesafe.int.exe.xyz/v1/systemone`. Both Jev versions receive the same planned request bodies; only the top-level `model` member differs. `payload_sha256` identifies the shared plan and `wire_request_sha256` identifies the exact sent body.

**Prices:** USD figures use the list price, $0.042 per million input tokens; output is free. They are list-price estimates, not invoices.

**Execution settings:** 16 workers, client limit 1000 requests/minute, up to 8 attempts on transport errors, 408, 429, 5xx and HTTP 499 `internal_error` (Retry-After honored); every failed attempt is kept.

**Jev 1.13 comparison:** "Jev 1.13" columns use the `jev-1.13.0` run in `results/state-position-v1` (same plan and request bodies).

**Served model labels:** `jev-1.14.0` (32454 requests). Requests needing more than one attempt: 17.

**Noise floor:** this study has no retest arm. Read Jev 1.14 differences against the Jev 1.14 retest noise measured by the retest arms in Studies 1 and 2 (`state-packing` `retest`, `question-fanout` `retest-useful`), not against Jev 1.13's.
