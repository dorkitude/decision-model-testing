# Study 2 results: question fan-out (openai-decisions)

Generated by `question-fanout report` from saved receipts. OpenAI Decisions `gpt-6-luna`; 20 seeded TREC DL queries (10 per year) × 100 BM25 candidates = 2,000 items. Every arm has the same one-passage state; only the questions in the request change. The scored target is always the frozen `useful` relevance question. Intervals are 95% query-cluster bootstrap intervals stratified by year; Holm covers the eight fan-out contrasts.

**Provider:** OpenAI Decisions API, model `gpt-6-luna` (normalized label `openai-decisions/gpt-6-luna`), endpoint `https://openai.int.exe.xyz/v1/decisions`, wire format `guide-2026-10-06` (the documented format of the public-beta guide, 2026-10-06; see `../openai-decisions-adapter/decisions/wire.go`). Every request is the frozen Jev request body of the same job (`payload_sha256` matches the Jev plan), translated by the shared adapter: the Jev state becomes the text `input`, and each Noul question becomes a `predicate` question with the same name and instructions.

**Probabilities:** Decisions predicates return the probability that the condition is true directly, so p is the API's own `probability`, with no derivation or approximation. Whether those values are rounded or tie is measured in *Score granularity* below, not assumed.

**Prices:** USD figures use the published list price, $0.10 per million input tokens; output tokens are not billed. They are list-price estimates, not invoices; regional or long-context multipliers, if any applied, are not modeled.

**Execution (first invocation):** 16 workers, client limit 300 requests/minute, HTTP timeout 300s; resumed invocations may differ (see `run.log`).

**Frozen Jev comparison:** `jev-1.13.0` columns replay the frozen 2026-09-25 run in `results/question-fanout-v1` (same plan, same request bodies).

**Served model labels:** `openai-decisions/gpt-6-luna` (26000 requests). More than one label means the snapshot changed during the run.

**Refusals:** a `refusal` answer is a non-answer. It is recorded in the receipt (`refused`), never retried, and never given a probability. Every metric excludes refused decisions, and each affected row or figure is tagged `[N refused, excluded]` with the count from the arms it is computed over. Paired comparisons (Δp, Δ AUC, nDCG differences) also drop pairs whose reference decision was refused; the reference row carries that count. nDCG@10 drops a query from a condition when any of its candidates was refused, because a ranking with a missing candidate is not comparable. **0 of 46000 scored decisions (0.00%) were refused**, plus 45 unscored co-asked questions.
