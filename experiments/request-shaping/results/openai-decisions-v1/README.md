# OpenAI Decisions request-shaping aggregates

## TL;DR

Request shape changed model behavior, but the useful pattern depended on the provider. Packing 100 passages raised Jev nDCG@10 by +0.036 and cut input tokens per decision from 438 to 189; Decisions gained only +0.015 with no token saving, while SubQ gained +0.015 at 10 passages but could not run larger packed-question arms because of a 16-question service limit. Co-asked questions were effectively independent when the target came first: mean probability changes matched Jev's 0.009 retest noise and were zero for Decisions and about 0.0001 for SubQ. SubQ's target moved about 0.013 when placed last among 16 questions. Long states showed no general “lost in the middle” effect, but SubQ favored the start of a 40-passage state by +0.0196 AUC over the middle; putting the question before the state helped Decisions most. Practical guidance is therefore provider-specific: use named references, freeze layout and ordering, validate packing empirically, and do not treat multi-question independence as position independence.

[`summary.json`](summary.json) holds the source-free numbers behind the [provider comparison](../../README.md#provider-comparison). It was generated by `publication/decisions-aggregates.py` in the private repository and lists the private source files it read with their SHA-256 (`sources`): each study's generated Decisions report, manifest and resources file. It contains numbers and machine identifiers only (arm names); no passage or query text, request bodies, receipts or raw provider responses.

Under `data.studies.<study>` (`state-packing`, `question-fanout`, `state-position`):

- `resources`: per arm, requests, scored decisions, reported input tokens (total and per decision), list-price USD at $0.10 per million input tokens, refused questions, request latency p50/p95 (HTTP round trip) and retried requests.
- `totals`: the same summed over the study.
- `report_tables`: every table of the generated Decisions report, keyed by section heading, one object per row with the report's column names. These include the Jev columns beside each Decisions estimate, the noise floor, refusal counts, score granularity and the same-request Decisions-versus-Jev comparison.

The human-readable provider reports cover [state packing](../state-packing-openai-decisions-v1/REPORT.md), [question fan-out](../question-fanout-openai-decisions-v1/REPORT.md) and [position in state](../state-position-openai-decisions-v1/REPORT.md). The corresponding Jev reports are [state packing](../state-packing-v1/REPORT.md), [question fan-out](../question-fanout-v1/REPORT.md) and [position in state](../state-position-v1/REPORT.md).

Costs are list-price estimates from reported usage, not invoices. Intervals are 95% query-cluster bootstrap intervals stratified by year.
